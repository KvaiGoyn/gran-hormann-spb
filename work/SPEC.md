# ГРАНЬ · сайт офиса в Санкт-Петербурге

Цель: отдельный бренд офиса с продукцией Hörmann, архитектурным дизайном, видео, 3D, отдельными страницами, калькулятором и приёмом заявок. Рабочее название — ГРАНЬ. Синий/жёлтый близки к Hörmann. Главный референс — hoermann.ru. Экспорт должен подходить к структуре установленного Битрикс, где шаблон размещается в `/bitrix/templates`.

## Решения и границы
- Главная; каталог; 6 страниц направлений; калькулятор; о компании; сервис; контакты; политика обработки заявок; 404.
- Пользователь разрешил придумать тарифы. Калькулятор использует явные демонстрационные тарифы из data/tariffs.json, с разбивкой по полотну/цвету/поверхности/приводу/монтажу/доставке. Это не прайс Hörmann и не оферта.
- Предпросмотр сохраняет заявки в D1; Bitrix-пакет имеет отдельный same-origin API, которое пересчитывает цену и сохраняет заявку в инфоблок. Внешние уведомления не включать без адресата; реальные реквизиты оператора пока не предоставлены.
- Локальный предпросмотр + существующая публикация Sites с сохранением текущей аудитории (публичная). Выгрузка шаблона в `/bitrix/templates/gran`; итоговые файлы и повторяемый админский установщик собираются в `release/`.
- Не добавлять неподтверждённые статус дилера, отзывы, адрес, телефон, гарантии или сроки.

## Приёмка и проверка
1. Все маршруты открываются напрямую с уникальными заголовками, неизвестный адрес возвращает 404 — HTTP smoke + браузерные переходы.
2. Выбор параметров меняет итог и разбивку, ошибки размеров блокируют расчёт — unit tests + браузер.
3. Заявка отправляется и существует в базе; повтор не дублирует, неверные поля/чужой origin отклонены — API tests + реальная отправка из браузера и чтение БД.
4. Десктоп/мобильный экран без горизонтального скролла, навигация и формы работают — фактический браузер.
5. 3D открывает ворота, меняет цвет, загружается лениво; reduced-motion учтён — браузер и тест траектории.
6. Production build и пакет для Битрикс собираются — `npm run build` / `npm run export:bitrix`; PHP-интеграция проверяется после установки в текущий Bitrix.

Затронуты: HTML/общие блоки, src, генератор страниц/сборка, сервер расчёта/заявок, D1/миграции, тесты, документация, Sites manifest.

## Bitrix: редактирование сайта из админки · 2026-10-19

### Цель
Перенести сайт с набора статических PHP-копий на структуру, где страницы собираются из отдельных редактируемых блоков Bitrix. Редактору должны быть доступны тексты, изображения, карточки товаров, тарифы, SEO и параметры заявок без правки исходного кода.

### Границы и предположения
- Сохранить текущий дизайн, адреса страниц и расположение шаблона `/bitrix/templates/gran`.
- Основные разделы сайта: общая шапка/подвал; главная; каталог и карточки продуктов; калькулятор; о проекте; сервис; контакты; политика; 404.
- Каждая секция страницы выводится из отдельной включаемой области и редактируется в визуальном режиме; общая шапка и подвал — общими областями, товары, SEO и тарифы — отдельными записями инфоблоков. Включаемая область — целый HTML-фрагмент, а не набор полей; порядок секций задаётся шаблоном. Установщик сохраняет существующие области при обновлении пакета.
- Навигация использует компонент `gran:site.menu`: основные пункты берутся из инфоблока меню, список под «Продукцией» — из активных направлений инфоблока товаров. Каталог выводится динамическим списком; каждая его карточка вызывается через `gran:product.card`, а общая страница товара — через `gran:product.detail`.
- Текущие тарифы остаются явно демонстрационными, пока владелец не предоставит коммерческий прайс. Не добавлять вымышленные телефон, адрес, реквизиты и получателя уведомлений.
- Источник: стандартные включаемые области и инфоблоки Bitrix; собственные шаблоны компонентов используются для карточек/страниц и расчёта. Пользовательское руководство Bitrix подтверждает режим визуального редактирования включаемых областей; документация разработчика описывает компоненты как контроллер данных плюс шаблон вывода.

### Приёмка
1. Каждая страница сайта открывается напрямую в Bitrix по прежнему URL; шапка, подвал, основные секции и продуктовые карточки представлены независимыми областями и редактируются из визуального режима.
2. Названия, описания, изображения, серии и ссылки 6 продуктов можно менять отдельно; повторно используемая карточка обновляется и на главной, и в каталоге.
3. Подписи и цены калькулятора редактируются через Bitrix; сервер заново считает итог по выбранным параметрам и не доверяет сумме, присланной браузером.
4. Формы принимают согласие и валидные поля, сохраняют заявку в Bitrix и показывают понятный результат. Уведомления отправляются только при настроенном адресате.
5. Заголовок, description и SEO-текст страницы редактируются из админки; медиа и внутренние ссылки указывают на существующие файлы и `/bitrix/templates/gran/`.
6. Установочный пакет можно распаковать в корень сайта, подключить шаблон и запустить повторяемую настройку инфоблоков без повреждения существующей базы.
7. Установка и просмотр публичных страниц проверены в текущей админке, а не только на локально собранном архиве.
8. Новое активное направление без экспорта появляется в каталоге и в выпадающих меню компьютера/телефона; общий адрес `/catalog/?product=<код>` открывает его страницу.
9. Пользовательские HTML-включаемые области переживают повторную установку пакета.
