# ГРАНЬ · Ворота и двери Hörmann

Многостраничный сайт отдельного офиса в Санкт-Петербурге. Рабочий бренд — «ГРАНЬ». В этой версии: 13 содержательных страниц + 404, каталог с фильтрами, индивидуальные страницы направлений, интерактивный 3D-шоурум, локальный архитектурный видеоролик, калькулятор со сметой и приём заявок в базу. Интеграция Bitrix установлена и проверена на сервере 19.10.2026.

## Запуск

Node.js 22.13+ (проверено на 26.10), npm. Первичная установка:

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_robust_toro.sql
npm start -- --port 4173
```

Первую миграцию выполнять один раз для новой локальной БД. `npm start` запускает собранную версию; после новой сборки перезапустить сервер. Для разработки: `npm run dev -- --port 4173` (изменённую вёрстку/JS предварительно пересобрать командой `node scripts/build-frontend.mjs`). Состояние базы хранится в `.wrangler/state`, не удалять при обновлении. Локальная БД и облачная D1 раздельны.

## Структура

- `index.html` — главная и общая оболочка; `scripts/page-content.mjs` — остальные страницы/формы.
- `src/main.js`, `src/style.css` — интерфейс и адаптивность. `src/gate-scene.js` — ленивый Three.js; анимация останавливается вне экрана.
- `data/tariffs.json` — стартовые демонстрационные тарифы, придуманные по запросу пользователя; это **не цены Hörmann**. Для Bitrix начальные значения редактируются в инфоблоках «ГРАНЬ: цены калькулятора» и «ГРАНЬ: настройки цен»; опубликованный калькулятор запрашивает их у сервера.
- `server/pricing.js` — общая чистая функция расчёта. Сервер пересчитывает цену, не доверяя сумме клиента.
- `server/leads.js`, `app/api/leads/route.ts` — обработка заявок в D1 предпросмотра. `scripts/bitrix/api/leads/index.php` — same-origin обработчик заявок Bitrix с повторной проверкой расчёта и сохранением в инфоблок.
- `scripts/build-frontend.mjs` собирает HTML/CSS/JS, затем Vinext отдаёт HTML по отдельным адресам. Полного React-гидратирования страниц нет.
- `web-public/media` — медиа; источники в `ASSETS.md`.

## Заявки

`POST /api/leads`, JSON, same-origin. Поля: `requestId` (UUID v4), `name`, `phone`, `message`, `topic`, `consent: true`, `website: ""` (honeypot), необязательная `configuration`:

```json
{"width":3000,"height":2250,"color":"anthracite","surface":"smooth","drive":"standard","installation":true,"delivery":"spb"}
```

Успех `201 {"id":"…","status":"stored"}` только после записи в базу. Идентичный повтор — `200`, конфликт тела с прежним ID — `409`. Невалидные поля — `400`, чужой Origin — `403`, лимит 8 заявок/час на дневной хеш IP — `429`, ошибка БД — `503`. Имя/телефон не кладутся в localStorage и логи. Публичного API чтения нет.

Локальный просмотр заявок владельцем:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --command 'SELECT id, created_at, name, phone, topic, message, quote_json FROM leads ORDER BY created_at DESC LIMIT 50;'
```

Облачные записи читать через доступ владельца к D1/Sites; локальная команда их не показывает. **Email/Telegram не подключены: получатель не задан.** Bitrix-обработчик сохраняет заявки в отдельный инфоблок, однако POST-запись на установленном сайте пока не проверялась. До коммерческого запуска нужны реальные контакты/реквизиты, утверждённые тарифы, политика и срок хранения данных.

## Bitrix

`npm run export:bitrix` собирает 14 PHP-страниц, 27 включаемых областей, серверный API и компоненты меню, списка, карточки и страницы товара. Путь шаблона — `/bitrix/templates/gran`; `/local/templates` не используется.

### Что правится в админке

- Направление каталога — отдельный элемент инфоблока «ГРАНЬ: товары и направления»: название, символьный код, описание, подробный текст, изображение, категория «Для дома/Для бизнеса», подпись, серии и ссылка на каталог производителя. Активные элементы автоматически появляются на главной и в каталоге, в меню на компьютере и телефоне; ссылка открывает `/catalog/?product=<код>`.
- Основные ссылки шапки — элементы инфоблока «ГРАНЬ: меню сайта»: название, адрес, сортировка и флаг «Только мобильное меню». Ссылка «Продукция» автоматически раскрывает список активных направлений.
- Тексты и HTML каждой секции, шапка и подвал — через «Изменить включаемую область». Это один редактируемый фрагмент HTML на секцию, не набор независимых полей для заголовка, кнопки, текста и изображения. Можно править сам фрагмент, но не переставлять секции местами в визуальном редакторе.
- Цены и подписи калькулятора — инфоблоки тарифов; SEO — отдельный инфоблок страниц; заявки — отдельный инфоблок для администраторов.

### Что остаётся в коде

- Внешний вид и разметка карточки и страницы направления, фиксированные заголовки/подписи/кнопки, хлебные крошки, число связанных направлений и правило «для кода garage показывать калькулятор». Товарные поля подставляются в эту разметку, но её структуру нельзя настроить отдельными компонентными параметрами в админке.
- Порядок секций страницы, стили и поведение фильтров. Вкладки «Для дома / Для бизнеса / Все решения» сейчас фиксированы; схема категории каталога содержит только два значения.
- Правило, что пункт меню с кодом `catalog` получает выпадающий список направлений. Свойства обычных пунктов меню редактируются через инфоблок.

Готовые файлы: `release/gran-bitrix-package.zip` и отдельный админский загрузчик `release/gran-setup.php`. Загрузчик перед обновлением сохраняет затрагиваемые файлы в `/upload/gran-backups/`, не перезаписывает существующие записи инфоблоков с тем же символьным кодом и сохраняет уже отредактированные включаемые области. Новые области при установке создаются из пакета.

19.10.2026 последняя сборка установлена на сайт. Повторная установка сохранила 27 уже отредактированных областей и создала резервную копию из 83 файлов: `/upload/gran-backups/gran-20261019-161208.zip`. Проверены 6 активных направлений, автоматическое появление тестового направления в каталоге и меню, затем тестовая запись ID 43 удалена окончательно. Общий адрес `/catalog/?product=garage` открывает страницу товара. Начальные суммы явно демонстрационные. Внешние уведомления не отправляются, пока не задан получатель. До коммерческого приёма заявок также нужны реквизиты оператора и утверждённая политика.

## Проверки и экспорт

```sh
npm test
node scripts/smoke.mjs http://127.0.0.1:4173
npm run export:bitrix
```

Smoke проверяет маршруты, их статусы, H1, связанные ресурсы и серверную валидацию. Локальная проверка экспорта не заменяет проверку установленного PHP/Bitrix: PHP runtime в локальной среде отсутствует. Установленный Bitrix проверен 19.10.2026; синтетический POST заявки не отправлялся. Исходные JS/CSS в репозитории хранятся читаемыми файлами; собранные файлы шаблона в `release/` генерируются и не добавляются в Git.

Тексты и структуру HTML внутри обычных секций можно менять по отдельности через «Изменить включаемую область». Карточки и тексты товара редактируются в инфоблоке, а общая разметка карточки/страницы остаётся кодовой. Редактору не требуется менять PHP-файлы для добавления нового направления.

Видеоплеер загружается по клику. Ролик хранится локально; ссылка на внешний официальный фильм указана отдельно. Первый экран — созданная архитектурная визуализация, а не выполненный объект. 3D-модель демонстрирует принцип движения и не является CAD конкретной серии. Не заявляется статус официального дилера.
